# OKX Trader GUI

基于 Python、PySide6 和 [python-okx](https://github.com/okxapi/python-okx) 的分阶段桌面交易软件。

## 当前功能

- 白色卡片合约监控界面，默认 BTC、SPCX 的 USDT 永续合约。
- 界面底部依次为「持仓信息」「委托」「下单」三个区域；持仓每 1 秒自动刷新，委托自动查询更新，下单区支持确认后发送订单；合约监控区在启动及添加、删除合约时按项目数量自动调整高度，项目较多时使用滚动条；也可拖动上下区域之间的分隔条手动调整高度。下方三个区域之间的细分隔条支持左右拖动调整宽度，区域缩窄时可滚动查看内容。
- 输入完整合约代码添加（例如 `DOGE-USDT-SWAP`），支持大小写归一化、格式校验、重复提示和删除。
- 点击「启动行情」订阅 OKX 公共 WebSocket `tickers`；各合约面板底部显示最新成交价和 UTC 零点起涨跌幅（北京时间每日 08:00 起）。
- 运行期间添加或删除合约会更新订阅；断线后自动重连，报价清空以避免显示过期价格。订阅失败会显示提示。
- 停止行情或关闭窗口会释放后台连接；没有合约时自动停止行情。
- 每个合约独立设置价格区间、区间内播报/静音和价格间隔，支持开始/停止阶梯式语音播报。开始播报会自动启动行情。

启动时自动连接 OKX 公共 WebSocket 并订阅默认合约行情，不需要 API 密钥；可点击「停止行情」暂停监控。语音播报仍需单独配置并开启。公共行情可独立使用，账户持仓需要配置 API 凭据；下单需配置具有交易权限的 API 凭据。合约格式在本地校验，合约是否存在由 OKX 订阅结果确认。

## 账户持仓

启动后从 `~/.config/okx-trader/credentials.env` 读取凭据，通过 [OKX 查询持仓接口](https://www.okx.com/docs-v5/en/#trading-account-rest-api-get-positions) 获取账户全部非零持仓，不限于上方监控列表。凭据文件格式如下（请填写自己的值，不要提交到仓库）：

```dotenv
apiKey=你的API密钥
secretKey=你的API密钥密文
passphrase='创建API时设置的口令'
OKX_FLAG=0
```

也支持 `OKX_API_KEY`、`OKX_SECRET_KEY`、`OKX_PASSPHRASE`。值中含空格或 `#` 时请加引号；文件只按文本解析，不执行 shell 命令。建议设置文件权限为 `600`。`OKX_FLAG=0` 为实盘（默认），`1` 为模拟盘，界面会标明账户环境。查询只需 API 的读取权限。

持仓区采用浅色卡片布局，显示合约名称、买/卖、全仓/逐仓、杠杆、收益额及收益率、币种持仓量、保证金、维持保证金率、开仓均价及预估强平价。合约数量按合约面值换算成币种数量，空单显示负数；面值获取失败时明确使用“张”作为单位。收益率及维持保证金率转为百分比，价格按合约价格精度展示，悬停可查看原始数值；接口未提供的字段显示 `--`。持仓查询在后台执行，每 1 秒刷新；修改凭据后下次查询自动重新读取。查询失败时保留上次数据，并通过持仓区悬停提示说明错误；尚无数据时在区域内显示错误，只有成功查询且无非零持仓时才显示「暂无持仓」。凭据缺失不影响公共行情和语音功能。

## 当前委托

中间「委托」区沿用浅色主题及 GUI 原字体，只参考订单卡片的信息布局。顶部显示当前委托总数；每项显示合约、委托类型、买入/卖出、保证金模式、接口返回的杠杆、创建时间，以及触发价格、委托价格和委托数量。普通委托还显示已成交数量；止盈止损、移动止盈止损等按实际字段显示。最新、标记、指数触发条件分别标明，`-1` 委托价显示为市价；合约数量按面值转换为币种数量，无法确认面值时使用“张”。币本位合约委托保留张数，避免按尚未发生的成交价换算。

使用同一凭据文件自动查询。通过 [普通未成交委托接口](https://www.okx.com/docs-v5/en/#order-book-trading-trade-get-order-list) 及 [策略委托接口](https://www.okx.com/docs-v5/en/#order-book-trading-algo-trading-get-algo-order-list)，查询整个账户的普通委托、计划委托、单向/双向止盈止损、移动止盈止损、冰山、智能冰山、时间加权及追价委托，不限于监控合约，并自动读取全部分页。委托按创建时间倒序排列，可独立上下滚动；普通委托和各类策略委托使用最多4个并发查询，并保持请求发起间隔限速；启动时查询一次，每轮查询完成后等待 1 秒再次查询；下单、撤单或修改委托后立即触发刷新，查询失败时保留上次完整数据，并在悬停提示中说明错误。首次查询失败时在区域内显示原因，成功且无委托时显示「暂无委托」。每条委托右侧提供“修改”和“撤单”：普通限价/只挂单、计划委托及止盈止损委托可修改对应价格和数量，其他策略的修改按钮禁用并提示。修改总数量包含已成交部分，合约数量以币数填写并按面值换算；面值不可用时不允许修改数量。计划及止盈止损的委托价格可填 `-1` 表示市价。

操作窗口显示委托编号、合约、交易环境，点击确认后才提交；提交前核对凭据、最新状态和交易规则。修改失败不自动撤销原委托，网络异常不自动重试，结果未知时须在 OKX 核对后关闭窗口。请求在后台执行，处理期间禁止关闭窗口；受理后刷新委托及持仓，最终状态以交易所更新为准。列表刷新不会覆盖正在编辑的输入。接口参考：[修改普通委托](https://www.okx.com/docs-v5/en/#order-book-trading-trade-post-amend-order)、[修改策略委托](https://www.okx.com/docs-v5/en/#order-book-trading-algo-trading-post-amend-algo-order)。

## 区间与阶梯式语音播报

每个合约右侧依次为「低价格」「高价格」「价格间隔」和「开始播报」，下方提供「区间内播报」复选框（默认不勾选）。先启动行情并等待实时价格，再填写设置并开始播报。

- 低价格留空默认为 0，高价格留空默认为正无穷大，因此可只填写一个价格。填写的低价格必须为大于或等于 0 的有效数字，高价格必须为大于 0 的有效数字；低价格必须严格小于高价格，填写的价格间隔必须大于 0；开启该合约“情况紧急”后允许留空，进入单次价格播报模式。上下限都留空、填写间隔时，使用开始播报时的现价作为阶梯基准。
- 开始时不要求现价位于 `[低价格, 高价格]` 内；现价已在区间外时立即按对应方向播报突破/跌破，并按已开启的紧急开关触发紧急循环。没有有效报价或价格设置不合法时仍弹出对话框，不启动播报。
- 未勾选「区间内播报」时，范围内及恰好处于边界均静音。勾选后，以启动时现价为基准，在区间内双向按价格间隔播报；在区间内开始时不立即播报，必须填写价格间隔。区间内按阶梯变化方向提示“行情有变，BTC价格上涨到……”或“行情有变，BTC价格下跌到……”。上下限均留空时同样播报上涨/下跌方向。
- 首次突破高价格时提示“BTC，价格突破……”，跌破低价格时提示“BTC，价格跌破……”；在区间外按间隔继续播报时保留对应方向的提示。“行情有变”提示和英文合约名提前合成并缓存；越界时中文部分连贯播报“价格突破/跌破＋价格”，合约名维持英文发音，价格维持中文逐位读法。“行情有变”的“变”以及突破/跌破的“破”均指定第四声降调音标。
- 在范围外按价格间隔继续双向阶梯播报，阶梯以对应边界为基准。跳过多个档位时只播报一次最新价格。
- 回到范围内清理该合约尚未播放的语音，当前语音继续播完；未勾选时恢复静音，勾选时以返回区间时的现价重新建立间隔基准。再次越界重新开始。直接从区间上方跳到下方也会按新的一侧播报。
- 各合约独立启停，运行时锁定输入；停止后可以修改设置。删除合约、停止行情或关闭窗口会清理对应播报。

例如不勾选「区间内播报」，低价格 `82400`、高价格 `82800`、间隔 `100`：现价 `82600` 时可以启动；`82400` 到 `82800`（含两端）内静音，涨到 `82801` 时首次播报，继续到 `82900` 时播报；回到 `82800` 静音。随后跌到 `82399` 时重新播报，继续跌到 `82300` 时播报。

### 只填价格间隔

上下限都留空时，点击「开始播报」会捕获当时实时价格作为基准，启动时不发声。每上涨或下跌一个间隔播报一次，反向走回前一档也会播报；一次跳过多个档位只播报当前价格一次。停止再开始会重新捕获当时现价。例：现价 82600、间隔 100，涨至 82700 或跌至 82500 时播报。同样支持小数间隔。

上下限都留空时，不受「区间内播报」复选框影响，仍按现价基准播报，提示保持“行情有变”，不提示突破/跌破。

此模式若打开上、下限旁的紧急圆点，则分别在向上或向下跨档播报时启动对应方向的紧急循环。仅一个边界留空时仍按价格区间和「区间内播报」选项工作。

### 不填价格间隔

至少填写一个价格边界，开启该合约的「情况紧急」，不勾选「区间内播报」，价格间隔留空即可开始播报。首次越界只播报一次合约名称和当前价格，随后在空档循环播报「情况紧急」；本轮即使继续涨跌、返回区间再越界，也不会再次播报价格。停止后重新开始会重置这一次播报。

该模式关闭紧急开关会同时停止该合约的播报。未开启紧急开关且未填价格间隔时，弹窗提示，不允许开始；填写 0 或非法间隔也不会被当成留空。

### 上、下限独立紧急开关

每个合约的低价格和高价格旁各有一个紧急圆点，灰色为关闭、红色为开启；悬停显示对应方向和状态。跌破下限只检查下限圆点，突破上限只检查上限圆点，两个方向独立启动和关闭。

所有方向共用串行播放器，价格播报优先，没有待播价格时循环播报「情况紧急」。多个方向同时报警时轮流播放，不重叠，不占价格待播队列容量。关闭某个圆点只停止对应方向的紧急循环；点击「停止播报」始终停止该合约的语音；本轮尚未触发紧急情况时保留圆点开关，已触发过紧急情况时同时关闭两个圆点（回到区间内也保留本轮触发状态），停止行情或关闭窗口会清理全部合约。

价格间隔留空时，至少开启一个方向的圆点，只有开启方向的越界可以触发单次价格播报和紧急循环；关闭全部圆点会同时停止该合约播报。填入价格间隔时，普通价格播报仍适用于上下两个方向，紧急循环只由对应已开启圆点的方向触发。「测试语音」不会启动紧急循环，所有提示共用音量设置。

Linux 优先使用 Piper 神经网络普通话音色 `zh_CN-huayan-medium` 离线生成 WAV（缺少模型时回退到 eSpeak NG），再使用 `paplay` 通过桌面音频系统播放，合成和播放均由异步 QProcess 执行，不阻塞 GUI。该普通话音色已经通过用户实际试听确认，比原来的 eSpeak 更自然，避免 speech-dispatcher 模块崩溃后仍显示播放状态却没有声音的问题。所有合约共用一个串行语音队列，当前播报完成才播放下一条，默认最多等待 5 条；队列满时丢弃最旧的待播内容，保留最新请求。回到范围内或行情重连只清理待播内容，当前语音继续播完；手动停止、删除合约或关闭窗口会立即停止。支持取消以及子进程错误提示，不发送行情到外部语音服务。其他平台或缺少本地播放工具时回退到 Qt TextToSpeech。

「测试语音」左侧提供 0–100% 音量滑块，默认 50%，0 为静音，调整对下一条播报生效，测试和行情播报共用此设置。点击「测试语音」可以不启动行情直接试听“行情有变”及 BTC 合约价格 82600.05（逐位读作“八二六零零点零五”）。合约名称只读基础币种，例如 `BTC-USDT-SWAP` 只读 `BTC`；合约名优先用离线 Piper 英文音色 `en_US-amy-medium` 逐字母发音并缓存，使用已试听确认的英文女声，英文语速较原版加快约 20%，与中文逐位价格的节奏匹配（缺少英文模型时回退到 eSpeak），价格仍用 Piper 中文音色；两段合成一条音频，压缩英文尾部及中文开头的多余静音，交界不额外插入静音，保留约 8 毫秒的边缘余量并交叉淡化，保持连贯且避免截断字音，按原队列播放。价格整数和小数均逐位读出，不转换为千、百等单位。此设置只调节应用播报，实际声音还受系统音量和输出设备影响。

自然语音只需首次下载模型，运行播报时完全离线。安装与下载：

```bash
.venv/bin/python -m pip install -e '.[dev,voice]'
mkdir -p .local/voices
.venv/bin/python -m piper.download_voices zh_CN-huayan-medium en_US-amy-medium --download-dir .local/voices
```

中文、英文模型各约 60 MB，保存在 `.local/voices`，不提交到 Git。来源：[Piper](https://github.com/OHF-Voice/piper1-gpl)、[Huayan 模型](https://huggingface.co/rhasspy/piper-voices/tree/main/zh/zh_CN/huayan/medium)。英文模型来源：[Amy 模型](https://huggingface.co/rhasspy/piper-voices/tree/main/en/en_US/amy/medium)。GUI 启动时在后台预加载并预热中英文 Piper 模型，并提前缓存默认合约英文名称，所有价格播报复用同一个常驻合成进程，避免每条都重新加载模型。本机双模型初次预加载约 6 秒（刚打开立即播报可能等待）；预热后默认合约合成实测约 0.16–0.25 秒，新合约首次生成英文名称约 0.37 秒，之后复用名称缓存。取消单条语音不会卸载模型，关闭窗口会结束进程；重复的“情况紧急”音频在本次会话中缓存复用。

Linux 需要 `pulseaudio-utils` 播放音频，可另安装 `espeak-ng` 作为备用：

```bash
sudo apt-get install espeak-ng pulseaudio-utils
```

本机的 eSpeak 可执行文件已放在 `.local/espeak/usr/bin/espeak-ng`，程序会自动识别（依赖系统已安装的 libespeak-ng 和 espeak-ng-data）。如需重建这个本地可执行文件：

```bash
mkdir -p .local/packages .local/espeak
cd .local/packages
apt-get download espeak-ng
cd ../..
dpkg-deb -x .local/packages/espeak-ng_*.deb .local/espeak
```

## 环境准备

推荐 Python 3.12；虚拟环境位于 `.venv`。

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

```bash
python -m pip install -r requirements-lock.txt
python -m pip install --no-deps -e .
```

## 启动

```bash
bash run_gui.sh
```

Linux Qt 桌面需要 `libxcb-cursor0`，可用 `sudo apt-get install libxcb-cursor0` 安装。本机因 sudo 需要密码，将 Ubuntu 软件包解包到了 `.local/qt`，启动脚本会加载该路径，不修改系统。重建本机本地库可执行：

```bash
mkdir -p .local/qt .local/packages
cd .local/packages
apt-get download libxcb-cursor0
cd ../..
dpkg-deb -x .local/packages/libxcb-cursor0_*.deb .local/qt
```

系统库完整时也可运行 `.venv/bin/python -m okx_gui`，或激活环境后运行 `okx-gui`。

```bash
.venv/bin/python -m pytest
```

## 结构

```text
src/okx_gui/app.py       GUI 与合约交互
src/okx_gui/market.py    python-okx 公共 WebSocket 后台线程、重连与行情解析
src/okx_gui/voice.py     阶梯触发规则和语音队列
src/okx_gui/audio.py     Linux 离线音频合成和桌面播放
src/okx_gui/synthesize.py  Piper 模型后台合成入口
tests/                  离线测试
run_gui.sh              本机桌面启动脚本
pyproject.toml          工程依赖和 pytest 配置
requirements-lock.txt   验收依赖快照
```

行情地址为 `wss://ws.okx.com/ws/v5/public`（默认 443 端口），频道及字段参照 [OKX API 文档](https://www.okx.com/docs-v5/en/)。UTC 零点起涨跌幅为 `(last / sodUtc0 - 1) × 100%`，与 App 的 UTC 周期一致；缺少有效开盘价时涨跌幅显示 `--`，实时价格照常更新。若所在网络无法连接该公共服务，界面会显示重试状态。

### OKX 实时主动买卖量图

原爆仓窗口现显示 OKX 公共 `trades` 成交推送的主动买卖聚合量：红色主动买入，蓝色主动卖出，每个时间区间两根相邻柱子。纵轴是合约成交量（张），按 `sz` 累加，既不是成交笔数，也不是金额；推送已聚合的数量不再乘以 `count`。依据 taker 的 `side` 区分方向，不表示开多/开空。

支持 1、5、15 分钟整点对齐聚合，每秒刷新，当前区间持续累加。切换周期使用相同缓存重新聚合；滚轮横向缩放，默认44组、范围10–125组。左上角显示当前区间的主动买入/卖出量，鼠标悬停可查看历史柱组的精确数量，横轴使用北京时间。

后台连接 `wss://ws.okx.com/ws/v5/public` 的 `trades` 频道，无需 API Key，使用 OKX 文本 ping/pong 心跳，断线自动重连；删除合约或关闭软件停止订阅。只累计接收到的成交，不补齐停机或断线期间的历史；空白时段的零值表示未收到数据，不保证交易所没有成交。首个区间可能不完整。

新缓存文件为 `~/.local/share/okx-trader/trade-volume.sqlite3`（支持 `XDG_DATA_HOME`），保留最近30天，以合约和 tradeId 去重。后台按秒批量写入，在同一事务中维护精确十进制分钟总量；图表只读取可见范围的分钟总量，不每秒扫描全部成交。旧爆仓缓存独立保留，不参与新图表，GUI 不再订阅 Bybit 爆仓流。

接口说明：[OKX 公共成交频道](https://www.okx.com/docs-v5/en/#order-book-trading-market-data-ws-trades-channel)。

### 实时资金费率曲线

每个合约的主动买卖量图下方显示 OKX 当前资金费率，曲线为蓝色，横轴为北京时间，纵轴为百分比。每秒通过公共 `/api/v5/public/funding-rate` 接口采集 `fundingRate`，使用本机成功收到响应的时间作为采样时间，接口更新时间不变时仍保留每秒采样；不是已结算历史费率，不年化。按本机采样时间直接绘制每条真实采样，仅显示连线、不绘制圆点，不分桶、不累加；时间轴随缓存数据自动展开，默认最少显示1小时、最多7天。绘图区支持滚轮横向缩放：向上放大、向下缩小，可查看1分钟至7天，右侧始终跟随最新时间；自动刷新保留手动缩放范围。鼠标悬停可查看附近采样的费率和时间。

SQLite 默认保存至 `~/.local/share/okx-trader/funding_rates.sqlite3`（支持 `XDG_DATA_HOME`），实时采样使用独立的 `funding_samples` 表，与旧结算历史隔离，自动去重并清理7天前的数据。重启恢复缓存。启动前及断线期间的实时历史无法补齐，不生成模拟数据填充空缺；长时间缺失时曲线断开。请求失败时保留有效缓存并自动重试。公共接口无需 API key。

接口说明：[OKX 当前资金费率](https://www.okx.com/docs-v5/en/#public-data-rest-api-get-funding-rate)。

资金费率请求默认读取 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` 环境变量。也可单独为资金费率接口指定 HTTP 代理，例如 `OKX_FUNDING_PROXY=http://127.0.0.1:7890 bash run_gui.sh`（请换成实际地址）。未设置时保持默认网络配置；修改后重启程序生效。若平台返回地区限制，请检查代理出口是否满足平台访问要求。

资金费率图叠加 OKX 实时价格：蓝色费率对应左侧百分比轴，橙色价格对应右轴，两条曲线共用时间轴及滚轮缩放。价格复用现有 OKX 行情推送，每秒采样，写入同一 SQLite 文件的独立 `price_samples` 表，保留最近7天并在重启时恢复。行情超过5秒未更新时暂停价格采样；长时间缺失时断开连线，不补造数据。采样和写盘在后台进行，不增加额外价格 REST 请求。

资金费率图支持 `Ctrl+滚轮` 独立缩放纵轴：光标在绘图区左半侧（含左轴）时缩放费率轴，右半侧（含右轴）时缩放价格轴。向上放大、向下缩小，围绕对应轴范围中点缩放；实时刷新保留各轴缩放比例。普通滚轮继续只缩放横轴。

资金费率图支持按住鼠标左键平移：左右拖动时间轴，上下拖动两条曲线及对应纵轴。查看历史时实时采集仍继续，但不会自动跳回最新时间；双击图表恢复跟随最新时间并重置纵轴平移位置。

### 下单区

采用常见合约交易表单布局：合约、开仓/平仓、全仓/逐仓、杠杆、限价/市价/计划委托、委托价格和数量（币），绿色和红色按钮分别预览多/空方向。布局参考 [OKX 开平仓流程](https://www.okx.com/en-eu/help/how-to-open-a-position-and-liquidation-in-the-contract)，沿用 GUI 原有浅色样式与字体。

下单区已通过 python-okx 接入订单发送。选择合约、开仓/平仓、保证金模式、杠杆、限价/市价/计划委托、数量（币），点击方向按钮后先在后台读取账户模式、合约规则及持仓，校验最小数量、数量步长、单笔上限、价格精度、杠杆上限及可平数量。确认窗口明确展示实盘/模拟盘和订单详情，默认点击“确认发送”后才核对杠杆（仅开仓，目标不一致时才调整）并发送订单；平仓沿用持仓杠杆。余额与保证金充足性由交易所最终校验。

交易环境沿用 `credentials.env` 的 `OKX_FLAG`（`1` 模拟盘，`0` 实盘），须有交易权限。支持合约模式/跨币种保证金模式下的单向/双向持仓，不主动切换账户持仓模式。支持已有持仓时提交相反方向的限价、市价或计划委托。单向模式下，反向成交先抵扣原持仓，超出部分形成反向仓位；双向模式按所选多/空方向独立开仓。单向模式的“平仓”仍使用 `reduceOnly`，不会反向开仓。自选合约与报价自动同步，切换合约清空输入；“最新”按钮不覆盖手填限价。

确认窗口可勾选“不再提示”，点击确认发送时保存选择；之后该账户及交易环境下点击下单按钮会在校验后直接发送。选择在重启后保留，按 API Key、站点和模拟盘/实盘区分；设置文件仅保存账户标识的哈希和开关，不保存密钥或口令。下单区“恢复下单确认”可清除所有免确认选择；勾选后取消本次下单不会保存选择。

发送前再次校验凭据、账户模式、交易规则和持仓；确认超过60秒需重新确认。每单使用独立客户订单号，仅发送一次，网络超时不自动重发，并尝试按客户订单号只读查询结果。仍无法确认时锁定再次发送，用户核对 OKX 委托/成交记录后才能手动解锁。订单受理不等于成交，受理后刷新持仓和委托。请求期间禁止关闭窗口；请求均在后台执行。杠杆设置和下单是两个独立请求，下单失败不会自动撤销已成功设置的杠杆。

下单数量按标的币数输入（如 BTC、SPCX），确认窗口同样显示币数。后台使用合约面值 `ctVal × ctMult` 换算 API 所需张数，最小数量、步长、单笔上限及可平数量均以币数校验和提示，不自动取整。确认后再次核对换算结果，规则变化需重新确认。当前支持面值以标的币计价的正向合约；反向合约或面值信息不完整时阻止发送。换算字段参考 [OKX 合约接口文档](https://www.okx.com/docs-v5/en/)。

计划委托支持最新价、标记价或指数价作为触发依据，触发后可选择限价或市价执行。触发价格和限价均校验合约价格精度；确认窗口展示触发条件。使用 OKX 计划委托接口提交，由交易所等待触发，受理后显示在委托区；网络异常时按计划委托客户订单号查询，不自动重发。

接口参考：[OKX 下单接口](https://www.okx.com/docs-v5/en/#order-book-trading-trade-post-place-order)。

账户 REST 请求（持仓、委托、校验、杠杆、下单）默认使用当前官方全球地址 `https://openapi.okx.com`，不再依赖 SDK 的旧默认地址。可在本机凭据文件设置 `OKX_API_DOMAIN=https://openapi.okx.com`；区域站点账户须指定对应的官方 `eea.okx.com`、`us.okx.com` 或 `tr.okx.com` HTTPS 地址，兼容显式指定 `www.okx.com`。确认窗口显示实际 API 地址。`50123` 是服务端产品交易权限拒绝；账户接口返回 `trade` 不足以证明特定加密资产订单获准。程序不自动切换站点或重试发送订单。

杠杆改为不可手填的下拉框。切换合约或全仓/逐仓时，后台读取账户可交易合约的 `lever` 上限及 `leverage-info` 当前设置；下拉框采用用户核对的 App 快捷档位：1、2、3、5、10、20、30、50、75、100倍，并过滤掉超过所选合约上限的项。接口未提供 App 快捷倍数清单，这份列表来自用户提供的 BTC App 选项。当前账户倍数不在列表中时，要求重新选择，不自动添加任意倍数。实际允许杠杆还受持仓风险档位影响，发送前再次校验并以交易所结果为准。规则读取失败会阻止开仓，点击旁边的刷新按钮可重试；平仓沿用现有杠杆。

下单延迟优化：每轮校验中的账户配置、合约规则以及平仓所需持仓查询并行执行；开仓不再请求无关的持仓数据。确认前后仍分别校验最新规则，保持单次发送、不自动重试。交易所返回订单号后，委托区立即显示“已受理，待同步”的临时记录，暂不可修改/撤销；真实列表返回后替换并去重。未出现在未成交列表中的临时记录最多保留10秒（例如已成交市价单），它不表示仍有挂单或已成交。

杠杆核对：开仓发送前通过 `GET /api/v5/account/leverage-info` 读取当前倍数，按合约、保证金模式及逐仓双向的持仓方向匹配。当前与目标相同则跳过 `POST /api/v5/account/set-leverage`；不同时调整一次，随后再次查询确认目标生效才下单。59669 明确显示当前/目标倍数及脱敏后的服务端说明，并停止本次下单；程序不自动撤销策略委托或停止机器人。查询失败、调整失败或结果未确认均不继续下单，平仓不调整杠杆。

下单、撤单和修改委托受理后立即唤醒持仓及委托刷新，不等待定时间隔。若旧查询正在进行，停止其后续分页/元数据请求，并丢弃被刷新请求替代的旧结果或错误；已发出的 HTTP 请求返回后立即开始新查询。持仓和委托保留定时查询，用于同步成交、计划委托触发及其他客户端操作引起的变化。

撤单反馈：请求受理后立即显示“撤单处理中”并禁用该条委托的操作按钮，同时独立查询该订单详情；只有确认已撤销、已成交或已触发等终态才立即移除。较旧的全量快照不会把已确认结束的订单重新显示；查询失败不会当作撤单成功，仍由定时全量查询同步。

下单诊断：准备订单时使用同一账户/环境查询交易账户余额，在下单区和确认窗口展示 API 张数及按委托价粗算的初始保证金（币数 × 价格 ÷ 目标杠杆）。该估算不包括费用、已有仓位抵扣和交易所风控计算，市价单不使用虚构价格估算。`totalEq` 是全账户折美元权益，不等于 USDT 的 `availEq`；余额为零时保留真实展示，不自动调整资产或撤单。

诊断日志保存在 `~/.local/state/okx-trader/orders.log`（轮转保存），只记录订单参数白名单、规则及 USDT 余额快照、环境和 API Key 哈希标识，以及脱敏后的 OKX `code/msg/sCode/sMsg`；不记录密钥、口令、请求签名或请求头。发单失败时界面完整保留这些原始错误字段。


## 接力委托

下单区选择“接力委托”，选择普通委托、计划/止盈止损委托或本次运行中已有的接力作为前置单，选择接力订单类型（普通委托或计划委托），填写限价/市价、方向及币数；计划委托还需填写触发价和触发依据。前置单完全成交后才向交易所提交该计划委托，之后由交易所等待价格触发；如果再接下一单，仍须等待该计划的实际订单完全成交。点击“创建接力”确认后保存在本地内存中，等待前置单完全成交，再自动重新校验并发送下一单；支持 A→B→C 多级接力，也可由同一前置单创建多条接力。每个新接力只能依赖已经存在的前置单，无法创建循环依赖。也支持计划、止盈止损委托作为前置单：触发后继续查询实际生成的全部普通订单，全部完全成交且累计数量达到计划数量才触发下一单。尚未支持追价、冰山、TWAP 等复杂策略作为前置单。

只有订单详情明确返回 `filled` 且累计成交量达到总委托量时触发。部分成交、撤单、查询失败或从未成交列表消失都不代表完全成交。发送时重新使用现有合约精度、币数换算、杠杆及可平数量校验；失败或结果不明不会自动重发，依赖该接力的后续接力停止。账户凭据或环境改变时停止相关接力。

委托区显示每条接力的前置关系、状态及失败原因。等待中的接力可以“取消接力”，同时停止依赖它的后续等待接力，不撤销交易所订单。退出程序取消所有尚未触发的接力，重启不恢复；已发送到交易所的订单仍有效。接力发送期间需等待请求结束后退出。接力成交检查在后台进行，每轮结束后由下一次计时触发，无须点击下单按钮。
